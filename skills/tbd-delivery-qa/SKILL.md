# 最终输出验证与交付

## 输入与产出

输入为实际交付文件、封装前视频和音频母带、当前源身份、编辑映射、字幕唯一源、渲染配置和制作授权记录。产出为绑定具体文件哈希的检查报告、交付说明和可恢复工程入口。

可使用 `ffprobe`、`ffmpeg`、波形分析及实际播放器；没有检测能力时记录未检查，不能填“通过”。机器验证、人工视听、创作者确认与已发布是不同状态。

## 封装前后分别验证

视频编码和最终音频封装应能独立验证。以完整画面流和完整音轨封装，分别核对起止；不要在音轨复制时仅凭视频限帧决定输出结束，也不要无依据用最短流截断。

复制已验证音轨时，比较封装前后编码音频包内容、数量、PTS / DTS、时长与 skip-samples 等裁剪信息，不比较可能因封装而改变的整个文件哈希。重新混音或编码时，以封装前母带核对预延迟、尾部覆盖、时长和听感。

首、中、尾和接头都要检查。中部波形“零延迟”不能证明开头正确或尾音完整；相机同步、处理延迟、编码预延迟与漏包是不同原因，不以统一提前若干毫秒掩盖问题。

## 检查矩阵

| 检查对象 | 验证方法与判定边界 |
|---|---|
| 制作依据 | 当前源哈希、映射和正文确认或本轮继续授权对应同一版本；不补写历史确认 |
| 文件完整 | 最终 MP4 全程解码，核对帧数、时长、画幅、恒定帧率、色彩标签与实际转换记录、必要轨道 |
| 源画面与剪口 | 按映射复核代表性源帧及保留段首中尾，区分正常帧量化和额外偏移 |
| 连续性与包装 | 片头接点、各机位、效果起落、裁框变化和尾帧；黑帧检测限定正文有效画面，排除设计黑区 |
| 同步与尾部 | 首中尾、每个接头与插入段；对比母带、最终解码音频及尾包覆盖 |
| 声音 | 最终整片响度与真峰，复听对白、笑声、剪口、片头和音效；数字不代表逐句平衡 |
| 字幕数据 | 一条一回合、断点保留、未知应答独立、无重复遗漏或意外时间重叠、SRT 与显示层同源；真实抢话需独立回合与支持并行字幕的契约，最小 JSON 示例不支持该方案 |
| 字幕呈现 | 实际字体测宽、两行上限、阅读时长、快速交接；不含内部标记，手机尺寸可读 |
| 完整视听 | 按实际播放尺寸看听全片；未做完整复核则明确未完成，不称发布终审通过 |

使用本项目默认参数时：横版 1920×1080，竖版 1080×1920，H.264 / 25 fps / SDR Rec.709 limited，AAC / 48 kHz / 双声道约 256 kbps，约 −16 LUFS 且真峰不高于 −1.5 dBTP。用户或平台目标不同则按实际目标检查；这些不是平台统一标准。

同步容差由测量方式和时间基准决定。可把新增封装偏移不超过 10 ms 作为初始工作要求，但它不能替代相机同步、帧量化或字幕词时的独立判定。

## 故障诊断与复验

1. 保存最小失败样本、文件身份、命令及失败时间点。将根因、触发条件、影响范围和可见症状分开记录。
2. 沿来源 → 同步 → 编辑映射 → 取帧或字幕分段 → 渲染 → 封装追踪数据，找出在哪个边界首次违反不变量。仅观察到输出错位不证明是相机同步问题。
3. 在拥有该不变量的共享层修复；检查受同一机制影响的全部输出，不积累按端点、句子或片段的例外。
4. 用原始触发条件证明修改前失败、修改后成立。在共享边界设置小型回归矩阵；只在编码器、容器或运行时语义不同处增加必要集成验证。
5. 重建受影响派生物，绑定新文件哈希并重验。未证明根因时称为诊断或缓解，不宣称彻底修复。

波形相关应适应处理方式：动态增益可能降低长窗相关，使用有依据的短窗与覆盖率，并用已知偏移的阳性对照检验检测能力。不能为了通过任意降低阈值。缩小图集只供定位；疑似字形或画面问题应回看实际视频和原尺寸帧。

## 交付记录

写清阶段、版本、时长、文件哈希、改动、输入与配置指纹、实际检查过的文件和时点、失败与修复证据，以及仍需复核的项目。附可播放 MP4、工程入口；字幕版附对应 SRT。

把推荐交付与失败候选分开，保留历史版本。反馈统一使用“版本＋该版播放时间＋问题＋希望效果”，注明时间基准。本地导出成功不等于上传或发布完成；上传按用户已有明确授权执行。
