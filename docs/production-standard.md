# TBD 剪辑规范

公开版 0.1 · 2026-10-13

TBD 的制作重点是让观众跟上一个真实的人怎样讲述、思考和回应。先做好清楚、连贯、可信的对话，再用切镜、字幕和少量综艺包装帮助理解。节奏可以紧，人物表达不能被改写。

这份规范提炼自实际制作与问题复盘。它公开可复用的做法，不包含原节目媒体、人物资料或私有制作记录，也不声称所有风格选择已经在各种设备和长节目中验证。

配套阅读：[风格指南](style-guide.md)、[制作流程](workflow.md)、[质量检查单](quality-checklist.md)、[数据契约](data-contracts.md)。

## 规则强度

| 标记 | 如何执行 |
| --- | --- |
| **必须** | 素材、内容、时间线和交付的正确性约束。不能为赶进度或画面好看而绕过。 |
| **默认** | 新节目可采用的起点。按素材、平台和编辑意图调整，并记录原因。 |
| **待验证** | 需要实际听看、手机预览或更多素材证明的选择。不能写成已通过。 |

## 1. 先保住人的意思

**必须：** 保留问题与回答的对应关系、否定词、数字、限定条件、笑点的建立与回应。不把其他时刻的表情移来制造反应，不凭转写猜测补出对白，不把编辑评论伪装成人物原话。

**默认：** 删除设备准备、明确的制作讨论及无内容作用的重复；保留有意义的思考、呼吸、笑声和自然收尾。以内容功能判断去留，不设删减比例、停顿长度或每分钟切镜配额。

ASR 空白只表示模型没有给出文字。它可能对应轻声、漏字、笑声、呼吸或重要停顿，不能直接转成删除区间。清理候选须回听原音并检查上下文；证据矛盾时保留并记录。

## 2. 完整横版先审，再做包装

**默认顺序：** 素材与同步 → 正文剪辑 → 完整纯横屏审片 → 字幕与包装 → 完整成片复核。

横版是完整、可播放、带同步对白的 16:9 审片文件。已完成内容取舍、多机位、基础构图、颜色和声音；不烧字幕，不加黑区、片头、花字或品牌层。短样片、抽帧和机器检查不能代替这一阶段的完整审片。

**必须：** 包装所依据的正文要能明确定位到版本、文件哈希、帧率、帧数和编辑映射。通常记录审核人对横版的确认；如果项目负责人已针对当前制作源明确授权继续，则按其范围执行，独立记录这次决定，不把旧横版追记成已通过。已有授权持续适用时不重复索要。

仅修改字幕或包装，可沿用正文依据。改变正文内容、顺序、镜头、基础声音或同步时，更新其映射与检查记录，按本轮授权范围决定是否重走正文审片。技术通过、内容审片、字幕听审和发布是四个不同状态。

## 3. 素材有身份，派生文件有来源

**必须：** 原始文件只读保留，所有加工写出新文件。记录稳定素材 ID、角色或机位、大小、SHA-256、实际时长、帧率、色彩信息、音轨和采样率。每个自动分段、重启文件都作为独立素材处理，不用文件长度假定接续关系。

首次使用素材应完整解码；核查首、中、尾及相邻分段。某机位缺录时优先用其他有效同步机位覆盖，不自动把整期截成所有机位的交集，也不用冻结帧伪造长时间覆盖。

收到调色、美颜或已剪辑的半成品时，明确它替代哪些画面和声音，并锁定其身份。旧转写和笔记只能作参考；不得在后续步骤悄悄混回旧源。代理用于预览与决策，最终输出使用指定的原片或高质量制作源。项目副本与同盘克隆均不能替代独立备份。

## 4. 所有层共用一份时间映射

**必须：** 镜头、声音、字幕、花字和效果音从同一编辑映射派生。视频统一使用半开帧区间 `[start, end)`；例如 `[0, 25)` 在 25 fps 下包含第 0 至 24 帧，共 1 秒。音频保留采样级或足够精度的时间。

分清三种坐标：

| 坐标 | 用途 |
| --- | --- |
| 素材时间 | 指定文件内的 PTS、入出点、同步偏移与经验证的漂移校正。 |
| 正文时间 | 保留和重排后的正文帧号，不含片头或插卡。 |
| 成片时间 | 含片头、插卡的最终帧号，用于实际交付与反馈。 |

任何删段、重排或插入都会改变映射。不能在改剪后继续给所有字幕加同一个偏移。若分析音频解码时归零，词时必须映回已选择的源时钟；片头偏移只加一次。容器起始 PTS、编码预延迟、skip-samples 与解码归零策略都要有明确处理。

同步以共同声音和媒体时钟为依据，设备时间只作辅助。覆盖首、中、尾和分段接头；仅测到持续漂移后才应用速度校正。一次相关峰、一次声纹判断或一个张口静帧均不足以证明整期同步或发言身份。

### 取帧与封装是不同的正确性边界

**取帧：** 长 GOP 等素材可能让一次 seek 后取得的画面偏离目标入点。检查解码 PTS 与目标源时间；必要时提前解码，再按源时钟裁切和转换帧率。不能把碰巧得到的第一帧重标为零，就认为它来自目标入点。正常帧率量化误差与额外偏移分别记录，容差按输入和输出帧率确定。

**封装：** 视频帧正确不证明声音首尾完整。完整画面流与完整音轨分别生成和检查，再进行最终封装。核对最终文件的首尾、音频呈现长度、预延迟和尾包；不能只测中段同步，也不能以固定毫秒补偿掩盖丢包或截尾。

问题复盘要区分根因、触发条件、影响范围与可见症状。在负责不变量的共享层修复，再复查全部受影响消费者；避免对每一条字幕或每一个剪口各补一个偏移。

## 5. 先判断说话回合，再排字幕

**必须：** 换人说话另起字幕。一个条目只表达一个说话回合；短应答、插话与归属不明的声音也不能为了增加阅读时长而合并到别人那一句。插话前后即便是同一人物，也可能是两个独立回合。

顺序固定为：回听与回合判断 → 语义分句 → 时间边界 → 一／两行排版。先检查原始 ASR 片段内部是否混有问答，再对确认同一回合的连续片段合句。字幕延长不得越过下一回合起点。真实重叠发言须回听并采用明确的并行字幕方案，不强塞进一个人的回合。

维护一份可编辑字幕源，保存稳定 ID、素材身份、时间基准、原文、说话人、回合、强制断点和独立疑点记录。显示字幕与 SRT 从它及相同映射生成，禁止分别改字。只改断句时，核对去掉空白后的文字顺序不变、保留片段恰好使用一次；纠字另记依据。

ASR 是定位和起稿工具。专有名词、数字、否定句及要突出展示的引言优先逐句回听；多个模型一致仍不能当作真值。字幕可纠错与合理断句，不擅自把人物的话改成更“正确”的书面表达。

**必须：** `待核`、`待审核`、`unknown`、模型分数及其他内部状态不进入字幕画面或交付 SRT。疑点保存在制作记录中；不得通过删掉否定词、数字或限定条件掩盖未听清的内容。

## 6. 声音与颜色先诊断，再处理

**声音必须：** 先抽听提问、叙述、抢话、笑声和安静段，确定每条轨实际录到了什么。双声道可能是相同的混合声，不能自动分配给两个人或丢掉一边。需要处理有损源时，先解码成保留余量的母带，再混合和调电平。

局部咂嘴与脉冲先定位、确认未与语音重叠，再局部修复和前后复听。全局去点击可能伤害辅音；插件名称不是整片套用的依据。承诺只改局部时，保留处理范围并检查其外部声音。已达标的制作源不重复叠加压缩、降噪或响度处理。

**颜色必须：** 检查色彩空间、传递曲线和范围；10-bit 不自动等于 HDR 或 Log，写标签不能代替转换。选择分散的同刻画面对比同一个人的肤色和共有中性物体，先曝光、白平衡与肤色，再考虑风格。不同单集不继承上一集的 gamma、裁框或饱和度常量。

## 7. 输出起点与未验证项

以下均为**默认**，不是平台官方要求。调整后在项目简报与交付记录中写明。

| 项目 | 起点 |
| --- | --- |
| 横版审片 | 1920×1080，16:9，完整、无包装、同步对白。 |
| 完整包装 | 1080×1920，9:16；横幅正文等比放入，详情见[风格指南](style-guide.md)。 |
| 视频 | MP4 / H.264，25 fps 恒定帧率，SDR Rec.709 limited；转换前检查源属性。 |
| 音频 | AAC，48 kHz，双声道，约 256 kbps；声道布局按实际媒体验证。 |
| 响度 | 整片约 −16 LUFS，真峰不高于 −1.5 dBTP，仍须逐句听感检查。 |
| 字幕 | 下黑区高对比白字，优先一行，最多两行；说话回合边界优先。 |
| 个人切片 | 第一帧进入正文，不加片头卡，不自动继承完整版片头。 |

**待验证：** 长节目中的效果密度与观看疲劳、极短应答的可读性、重叠发言、手机平台遮挡、不同设备的漂移与色彩变化。片头长度、常驻品牌比例和冷开场形式不设永久答案。

## 8. 交付的结论必须和证据相配

每个版本附媒体文件、工程入口、编辑映射、变化说明和检查报告；含字幕的版本另附同源 SRT。记录检查对应的文件身份、方法、位置、实际范围和未完成项。抽帧不等于连续观看，完整解码不等于完整听审，本地渲染不等于上传或发布。

反馈使用“版本 + 该版播放时间 + 问题 + 期望效果”。先定位发生在素材、映射、取帧、回合、渲染还是封装层，再改负责该问题的机制。历史交付递增保留，新导出绑定新的检查结果。执行时使用[质量检查单](quality-checklist.md)与[审片报告模板](../templates/review-report.md)。
