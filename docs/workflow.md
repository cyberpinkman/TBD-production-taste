# 从素材到交付

流程按依赖推进：先确定用什么、讲什么，再统一时钟，完成可审的正文，最后制作字幕与包装。任一步都可以做短样片验证风险，但样片不代替该阶段的完整交付。

规则细节见[制作规范](production-standard.md)，视觉取舍见[风格指南](style-guide.md)，交付前执行[质量检查单](quality-checklist.md)。可从[单集简报模板](../templates/episode-brief.md)起步，使用[审片报告模板](../templates/review-report.md)记录证据。

## 阶段 0：写一页简报

明确受众、主题、正文范围、完整节目或切片、需要的画幅、当前制作源、审核人以及本轮允许的处理。未知字段写未知，不用猜测填齐。用稳定的 `host`、`guest`、`cam_wide` 等 ID 管理角色与机位；ID 不承担身份识别的证明作用。

建立每期入口，顶部只回答：推荐看哪一版、当前在哪个阶段、最近决定是什么、下一步缺什么。将确认与授权、技术检查、人工审片、发布状态分开记录。

**进入下一步的条件：** 已知可以处理的素材与内容范围；未到齐的素材被列明，不影响的工作可先做。例如先收到音频，可先定位内容和建立候选编辑笔记，待画面到齐再同步。

## 阶段 1：入库与诊断

1. 建素材清单，记录 ID、身份、哈希、媒体参数和来源关系，保留原文件。
2. 找齐自动分段与重启文件，标明缺录、损坏、分享压缩版和处理后的版本。
3. 首次使用完整解码，抽看各文件首、中、尾；对比时长与实际覆盖。
4. 抽听每条音轨，确认它是独立人物、混合声还是相同的双声道，记录选用依据。
5. 建可重建代理供定位；明确最终要用的原片或指定制作源，不让代理成为唯一存档。

**产物：** 素材清单、可用范围、当前媒体方案、已知问题。清单记录“某机位缺了一段”时，尚不能推导出“这段内容要删”。

## 阶段 2：同步与内容图谱

选择覆盖充分的参考时钟，利用共同声音建立每个文件到参考时间的关系。核查首、中、尾和所有分段接头；根据测量决定是否需要漂移校正。参考时钟不决定哪个画面或音轨必须全程使用。

将 ASR 作为检索草稿：标出主题、问答、疑点、设备讨论、可能的笑点和收尾。先回听与确认保留范围，再细化镜头。听不清的地方保留疑点，不用模型分数或多遍一致代替证据。

**产物：** 同步映射、主题导航、候选保留区间、疑点表。源时间、正文时间和成片时间的字段不得混用，结构见[数据契约](data-contracts.md)。

## 阶段 3：完成正文

按主题和问答确定保留段，建立半开帧区间编辑映射，再派生声音和镜头。稳定讲述用合适近景；互动、归属不明或机位不足时选有效全景或同时刻反应。不要按固定秒数轮换。

收紧停顿前回听实际音频，保留语音边缘、必要呼吸和情绪。每个删段检查词头、句尾、动作和底噪；短淡变也不能跨掉发言或改变同步。基础调色先匹配曝光、白平衡和肤色；声音先处理实际问题，再评估整片响度。

长 GOP、变帧率或新转码链路先验证代表性入点的源 PTS 与输出帧对应；不要等全片完成后才发现共享取帧错误。

**产物：** 完整纯横屏、无字幕与包装的审片文件，以及映射、版本说明和有限检查记录。

## 阶段 4：记录正文审片结论

请审核人按完整横版反馈：内容是否连贯，问题与回答是否正确，切点、反应镜头、声音与口型是否自然。反馈写为“版本 + 播放时间 + 问题 + 期望效果”，注明用的是该版正文时间。

记录确认对应的文件身份与映射。要求返修则更新横版；若负责人已针对当前制作源明确授权继续，锁定该源与本轮范围，保留原审片状态。已有授权不重复索要，机器检查也不能替人推定确认。

**进入包装的条件：** 已有适用的正文确认，或针对当前制作源的明确继续制作授权。状态应描述事实，例如“正文已确认，字幕未听审”；不要笼统写“全片通过”。

## 阶段 5：字幕与包装

先将字幕对齐当前制作源，判断说话回合和强制断点，再合句与排版。逐句听审关键字、数字、否定句及引言，维护独立疑点记录。字幕层和 SRT 从同一字幕源与编辑映射生成。

根据[风格指南](style-guide.md)建立黑区、字幕、主题和效果层。每个效果绑定真实源事件与上下文，关键词说出后再出现。个人切片第一帧进正文；完整节目的片头逐集核对。

先导出能覆盖风险的代表片段：快速交接、极短回应、长字幕、人物动作、画内效果、切镜和片头接点。用实际字体与手机尺寸检查，再做全片。这里验证的是排版和实现，不能代替全片听审。

**产物：** 字幕唯一源、同源 SRT、回合与修订记录、包装配置、资产来源、风险样片和完整候选版。

## 阶段 6：渲染、封装与验证

记录素材、映射、字幕、配置、字体、工具版本和渲染命令的输入身份。确定性动画以帧驱动；不依赖未固定种子的随机数、系统时间或临时远程资源；使用随机效果时记录固定种子。缓存必须随输入变化失效。

先完成画面流和完整音轨各自的检查，再进行最终封装。只改字幕或包装且声音未变时，优先保留已验证的声音；使用声轨复制时，核对包内容、数量、PTS/DTS、时长及裁剪信息。重新编码时对比封装前母带的呈现起止、首中尾同步和尾部覆盖。

最终 MP4 重新完整解码，核对帧数、时长、轨道、画幅、色彩与恒定帧率。全文字幕、实际画面和完整声音仍需各自检查。黑帧检测限定正文有效区域，避免把设计黑区当故障。

**产物：** 可播放交付文件及绑定该文件身份的检查报告。未实际完成的检查写明待做。

## 阶段 7：交付与续作

交付入口注明阶段、版本、时长、改动、实际检查范围和待办；附工程入口、编辑映射、字幕附件与包装配置。媒体文件存在、技术检查通过、内容已确认、本地导出完成与已发布，分别记述。

收到返修先定位责任层：

| 现象 | 先核查的机制 | 重验范围 |
| --- | --- | --- |
| 删段后字幕整体偏移或花字错位 | 源 → 正文 → 成片映射、坐标字段和偏移是否重复应用 | 受影响字幕、花字、声音和镜头。 |
| 每个片段开始处画面都晚一点 | 解码 PTS、seek、归零和换帧率顺序 | 使用相同取帧机制的所有段，含首、中、尾。 |
| 换人时字幕仍在一条里 | 原始片段内的回合识别与合并边界 | 共享合并规则的全部条目。 |
| 中段同步正常但末尾声音缺失 | 封装终止条件、音轨包和呈现尾部 | 最终封装及同流程输出，不能只补时间偏移。 |
| 缩略图疑似破图或错字 | 实际成片、原尺寸无损帧、查看器与缩放 | 先确认症状，再决定是否重渲染。 |

表格是诊断入口，不是自动归因。先重现导致不变量破坏的条件，保留修前／修后证据，再修共享层。只重建受影响依赖，递增保留版本；不为了目录整齐搬走仍被工程引用的资产。

## 可复用的最小记录集

每期至少保留：素材身份、同步映射、编辑映射、声音／颜色处理依据、字幕唯一源、回合与疑点、包装配置与资产使用依据、工具版本、交付身份、检查范围、审核决定。字段定义以[数据契约](data-contracts.md)为准，避免分别发明互不兼容的时间格式。

本仓库的示例与检查工具用于建立这些约束，不替代有真实素材的剪辑器、渲染器或人工审片。
